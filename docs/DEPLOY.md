# Трекер на своём сервере

Что получится: трекер по адресу `https://ваш-домен`, данные — в PostgreSQL на вашем сервере,
сертификат HTTPS получается и продлевается сам, копия базы делается каждую ночь. Работают четыре
контейнера Docker, всё описано в папке [`deploy/`](../deploy). На всё уходит 20–30 минут.

## Что понадобится

- **VPS** с Ubuntu 24.04 (подойдёт и 22.04 или Debian 12): 1 ядро, 1 ГБ памяти, от 15 ГБ диска.
  Хватит самого простого тарифа: трекер в работе занимает около 200 МБ памяти, сборке нужно ещё
  до 400 МБ. Нужен публичный IPv4-адрес — он есть почти у всех тарифов.
- **Домен или поддомен**, например `tracker.example.ru`. Без домена сертификат HTTPS не выдают.
  Подойдёт поддомен своего домена или бесплатный, например на [duckdns.org](https://www.duckdns.org).
- **Доступ по SSH** — адрес, логин и пароль (или ключ) из письма провайдера.

## 1. Домен

В панели, где куплен домен, добавьте A-запись: имя `tracker` (или `@` для самого домена),
значение — IP сервера. Проверка с вашего компьютера:

```bash
ping tracker.example.ru      # должен показать IP сервера
```

Новая запись расходится от нескольких минут до пары часов, пока можно делать следующие шаги.

## 2. Подготовка сервера

Подключитесь к серверу (на Windows — в PowerShell или Windows Terminal):

```bash
ssh root@IP-сервера
```

Дальше все команды — на сервере. Обновления и Docker:

```bash
apt update && apt upgrade -y
curl -fsSL https://get.docker.com | sh
docker compose version       # ответ вида «Docker Compose version v2…» — всё на месте
```

Если `get.docker.com` недоступен, Docker есть и в репозитории Ubuntu:
`apt install -y docker.io docker-compose-v2 docker-buildx git`.

На сервере с 1 ГБ памяти добавьте файл подкачки — запас на время сборки:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

Файрвол: снаружи нужны только SSH и веб.

```bash
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw enable
```

Если у провайдера есть свой файрвол в панели управления, откройте в нём порты 22, 80 и 443.

## 3. Код и настройки

```bash
git clone https://github.com/RAKOVpy/tracker.git
cd tracker
git checkout claude/fervent-faraday-f7chiv     # ветка с последними этапами, пока они не в main
cd deploy
./setup.sh tracker.example.ru
```

`setup.sh` создаёт файл `deploy/.env`: домен, случайные пароли базы и ключ Django. Остальное в нём можно
поправить (`nano .env`): часовой пояс (по умолчанию московский), время и сроки хранения копий,
облако для копий. Файл виден только root — в нём пароли, в git он не попадает.

## 4. Запуск

```bash
docker compose up -d --build
```

Первая сборка занимает 3–5 минут. Проверка:

```bash
docker compose ps
```

Все четыре сервиса — `Up`, у `db` и `app` — `(healthy)`. Откройте `https://tracker.example.ru`:
появится экран «Первый аккаунт» и замок в адресной строке. Сертификат Caddy получает в первые секунды после
запуска. Если не получилось, смотрите раздел «Если что-то не так».

## 5. Аккаунт

Сразу после запуска зарегистрируйтесь на сайте: почта и пароль. **Первый аккаунт становится администратором**,
поэтому не откладывайте — иначе им станет тот, кто зарегистрируется первым.

У администратора в «Настройках» есть раздел «Сервер»:

- **Открытая регистрация** — по умолчанию включена: аккаунт может завести любой, кто откроет сайт.
  Когда семья и друзья зарегистрировались, снимите флажок — кнопка «Зарегистрироваться» исчезнет.
- **Аккаунты** — кто зарегистрирован и когда последний раз входил.
- **Временный пароль** — если кто-то забыл свой. Писем сервер не отправляет: временный пароль
  вы передаёте сами, а владелец аккаунта меняет его в «Настройках» → «Аккаунт».
- **Удалить** — аккаунт со всеми его данными, например чужой или пустой.

Ещё администратору открыта админка Django: `https://tracker.example.ru/admin/` — с той же почтой и паролем.

Если регистрацию не хотите открывать даже на минуту, перед запуском поставьте `ALLOW_REGISTRATION=0` в `.env`
и создайте аккаунт командой (пароль она спросит дважды, он не отображается):

```bash
docker compose exec app python manage.py adduser me@example.com --admin
```

## 6. Перенос данных с компьютера

1. В трекере на своём компьютере: «Настройки» → «Данные» → «Скачать резервную копию».
2. В трекере на сервере: войдите, «Настройки» → «Восстановить из файла», выберите копию → «Заменить данные».

Хранилище Obsidian подключите заново в настройках трекера на сервере: доступ к папке
у каждого сайта свой. Синхронизация работает в Chrome и Edge на компьютере.

## Резервные копии

**Автоматически** — каждый день в 03:30 (`BACKUP_TIME` в `.env`) и сразу при первом запуске.
Копии лежат на сервере в `~/tracker/deploy/backups`, файлы вида `tracker-2026-10-01_033000.dump`
(полная копия базы: все аккаунты и данные). Хранятся все копии за 14 дней, из более старых —
последняя копия каждой недели за 8 недель и каждого месяца за год. Лишние удаляются сами.

```bash
cd ~/tracker/deploy
ls -lh backups                        # какие копии есть
docker compose exec backup backup now # сделать копию сейчас
docker compose logs backup            # журнал: когда делались копии и были ли ошибки
```

**Восстановление.** Если данные испорчены или удалены по ошибке:

```bash
./restore.sh backups/tracker-2026-10-01_033000.dump
```

Скрипт спросит подтверждение, сначала сделает копию того, что в базе сейчас (передумаете — восстановите
её так же), и на несколько секунд остановит сервер. Копия загружается во временную базу и заменяет
рабочую, только если загрузилась целиком: битый файл базу не тронет.

**Копия у себя.** Копии на том же сервере не спасут, если сломается сам сервер. Время от времени
забирайте их на свой компьютер (команда — на компьютере, не на сервере; в Windows работает в PowerShell):

```bash
scp -r root@IP-сервера:tracker/deploy/backups ./tracker-backups
```

**Копия в облако — автоматически.** Подойдёт любое S3-совместимое хранилище: Yandex Object Storage,
VK Cloud, Selectel, Backblaze B2. На примере Yandex Object Storage:

1. В консоли Yandex Cloud создайте бакет (приватный) и сервисный аккаунт с ролью `storage.editor`,
   а для аккаунта — статический ключ доступа: идентификатор ключа и секрет.
2. В `deploy/.env` в конце уберите `#` у строк `BACKUP_REMOTE` и `RCLONE_CONFIG_CLOUD_*`, впишите имя
   бакета, идентификатор ключа и секрет.
3. Примените и проверьте:

   ```bash
   docker compose up -d
   docker compose exec backup backup now     # в конце: «копии отправлены в cloud:…»
   ```

После каждой ночной копии новые файлы уходят в облако. Оттуда копии не удаляются: если нужно, задайте
в настройках бакета правило жизненного цикла, например «удалять объекты старше 365 дней».

**Переезд на другой сервер** — шаги 1–4 на новом сервере, затем скопируйте туда файл копии
(`scp` с компьютера в `~/tracker/deploy/backups`) и запустите `./restore.sh`. Аккаунты и пароли — внутри копии.

Ещё одна страховка — JSON-копия из «Настроек» трекера: только ваши данные, её можно загрузить и в трекер
на компьютере.

## Обновление

Когда в репозитории появилась новая версия:

```bash
cd ~/tracker/deploy
./update.sh
```

Скрипт делает копию базы, забирает код (`git pull`), пересобирает и перезапускает контейнеры.
Миграции базы применяются сами при запуске. Трекер недоступен несколько секунд.

## Полезные команды

Все — в папке `~/tracker/deploy`.

| Команда | Что делает |
|---------|------------|
| `docker compose ps` | состояние сервисов |
| `docker compose logs -f app` | журнал сервера, выход — Ctrl+C |
| `docker compose logs web` | журнал Caddy: сертификат, ошибки прокси |
| `docker compose restart` | перезапуск всего |
| `docker compose down` / `up -d` | остановить / запустить; данные остаются |
| `docker compose exec app python manage.py changepassword me@example.com` | новый пароль, если администратор забыл свой |
| `docker compose exec app python manage.py adduser почта --admin` | новый аккаунт-администратор; у существующего — права администратора |

Не запускайте `docker compose down -v`: ключ `-v` удаляет том с базой.

## Если что-то не так

**Сайт не открывается или браузер ругается на сертификат.** Обычно домен ещё не указывает на сервер
или закрыт порт 80 либо 443. Проверьте `ping домен` (должен быть IP сервера) и файрвол в панели провайдера,
затем посмотрите `docker compose logs web | grep -i error`. Caddy повторяет попытки сам, а после исправления
можно ускорить: `docker compose restart web`.

**Не скачиваются образы** (`docker compose up` долго висит или пишет `429 Too Many Requests`, `connection refused`):
Docker Hub ограничивает число скачиваний, из некоторых сетей бывает недоступен. Помогает зеркало.
Если файла `/etc/docker/daemon.json` ещё нет:

```bash
echo '{"registry-mirrors": ["https://mirror.gcr.io"]}' > /etc/docker/daemon.json
systemctl restart docker
```

Свои зеркала есть и у многих провайдеров VPS — адрес ищите в их документации.

**Сборка обрывается со словом `Killed`** — не хватило памяти. Добавьте подкачку (шаг 2) и повторите.

**Сборка будто зависла** — долго не меняется строка `npm ci` или `pip install`. Откройте второе окно SSH
и посмотрите `free -h` и `top`. Если процесс занимает процессор (`node`, `pip`), сборка идёт: на слабом VPS
первая может занять до 10 минут. Если почти нет свободной памяти и подкачка (`Swap`) не настроена,
остановите сборку (Ctrl+C), добавьте подкачку (шаг 2) и запустите `docker compose up -d --build` снова:
уже скачанное повторно не скачивается.

**По IP-адресу сайт не открывается** — так и задумано: сертификат выдан на домен, и трекер отвечает
только на домен из `.env`.

**Сменить домен** — поправьте `DOMAIN` в `.env` и запустите `docker compose up -d`: Caddy получит новый сертификат.

**Первым зарегистрировался не тот аккаунт** или администратором нужно сделать ещё один —
`docker compose exec app python manage.py adduser почта --admin`, затем удалите лишний аккаунт в «Настройках» → «Сервер».

**Заканчивается место** — `df -h` покажет диск, `docker system df` — сколько занимает Docker.
Кэш сборки чистит `docker builder prune`, его же старую часть убирает `update.sh`.

## Как это устроено

```
интернет ──:80/:443──► web (Caddy) ──/api, /admin, /static──► app (Django + gunicorn) ──► db (PostgreSQL 18)
                        └─ остальное: собранный фронтенд                                     ▲
                                                                  backup (pg_dump каждую ночь) ┘──► deploy/backups ──► облако
```

- **web** — Caddy: получает и продлевает сертификат Let's Encrypt, перенаправляет http на https,
  отдаёт фронтенд и проксирует API. Единственный контейнер, открытый в интернет.
- **app** — Django с gunicorn: при запуске применяет миграции, отвечает только на домен из `.env`.
- **db** — PostgreSQL 18, данные в томе Docker `tracker_pgdata`. Снаружи недоступна.
- **backup** — копии по расписанию, их хранение и отправка в облако.

Защита: заголовки HSTS и Content-Security-Policy (на странице выполняются только скрипты самого трекера),
куки только по HTTPS и недоступны скриптам, попыток входа — не больше 20 в минуту с адреса, регистраций — 10 в час,
файлы копий читает только root.

Файлы:

| Файл | Что в нём |
|------|-----------|
| `Dockerfile` | сборка образов: фронтенд, сервер, веб-сервер, копии |
| `deploy/compose.yaml` | сервисы, тома, порты, проверки здоровья, ограничение логов |
| `deploy/Caddyfile` | домен, HTTPS, заголовки безопасности, кэш, маршруты |
| `deploy/.env.example` | все настройки с пояснениями |
| `deploy/setup.sh` | первая настройка: `.env` со случайными паролями |
| `deploy/update.sh` | обновление: копия, код, пересборка |
| `deploy/backup.sh` | копии: по расписанию, вручную, хранение, облако, загрузка копии |
| `deploy/restore.sh` | восстановление базы из копии |
